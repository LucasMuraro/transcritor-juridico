📦 Stack Frontend — O que cada tecnologia faz no ERP

Imagine que o ERP é uma casa. Cada tecnologia tem um papel específico na construção.

⬛ Next.js 14 (App Router)

O que é: É o gerente geral da aplicação. Next.js é um framework que fica em cima do React e resolve os problemas mais difíceis: roteamento, performance e segurança.

No ERP da SafeWork: Ele controla TODAS as páginas: /login, /clientes, /faturamento, /exames. Cada pasta vira uma rota automaticamente.

App Router: É o sistema de pastas novo do Next.js onde você cria um arquivo page.tsx dentro de uma pasta e ele já vira uma página do ERP.

📋 Papel no ERP: Estrutura de páginas, performance e backend-in-one (API Routes)
// Estrutura de pastas = Rotas do ERP
app/
  login/page.tsx   → erp.safework.com/login
  clientes/page.tsx → erp.safework.com/clientes
  api/nf/route.ts  → API interna /api/nf
⚛️ React 18

O que é: É a linguagem visual do ERP. React permite criar interfaces interativas usando "componentes" — pedaços reutilizáveis de tela.

No ERP da SafeWork: A tabela de clientes é um componente. O modal de confirmação de NF é um componente. O botão verde "Emitir" é um componente. Você escreve uma vez, usa em qualquer lugar.

📋 Papel no ERP: Interatividade — o que acontece quando o usuário clica, digita ou filtra dados na tela
// Componente React — Botão reutilizável
export function BotaoEmitir({ clienteId }) {
  return <button onClick={() => emitirNF(clienteId)}>
    Emitir NF
  </button>
}
🎨 TailwindCSS

O que é: É a tinta e o pincel. Tailwind é um sistema de CSS onde você aplica estilos diretamente no HTML usando classes pré-prontas, sem escrever CSS separado.

No ERP da SafeWork: Em vez de criar um arquivo estilo.css, você escreve diretamente: bg-blue-600 text-white rounded-lg px-4 py-2 e o botão já sai estilizado.

📋 Papel no ERP: Aparência visual — cores, tamanhos, espaçamentos, responsividade mobile

🧩 shadcn/ui

O que é: É uma biblioteca de componentes prontos e bonitos. Botões, tabelas, formulários, modais — tudo já existe e você só usa.

No ERP da SafeWork: A tela de listagem de clientes vai usar o componente <Table> do shadcn, com ordenação e paginação prontas. O modal de confirmação de exclusão usa o <Dialog>.

📋 Papel no ERP: Velocidade de desenvolvimento — não reinventa a roda, já tem tudo pronto
🔷 TypeScript

O que é: É o revisor gramatical do código. TypeScript é JavaScript com tipos, o que significa que o editor avisa ANTES de rodar se você cometeu um erro.

No ERP da SafeWork: Se você tentar passar o campo errado para a função de criar cliente (ex: esquecer o CNPJ), o TypeScript sublinha em vermelho antes mesmo de salvar o arquivo. Evita bugs em produção.

📋 Papel no ERP: Segurança do código — menos bugs, mais confiança para alterar código em produção
// TypeScript "avisa" se faltar campo obrigatório
type Cliente = {
  id: string
  cnpj: string // obrigatório!
  empresa_id: string
}
// ❌ ERRO — cnpj está faltando
const c: Cliente = { id: '...' }
🔄 React Query (TanStack Query)

O que é: É o mensageiro inteligente entre a tela e o banco de dados. Ele busca os dados, guarda em cache (memória) e sabe quando precisa atualizar.

No ERP da SafeWork: Quando o funcionário abre a lista de clientes, o React Query busca os dados uma vez e guarda. Se ele navegar para outra tela e voltar, não faz nova requisição — já está em cache. Só busca de novo se os dados ficarem "velhos".

📋 Papel no ERP: Performance e sincronização de dados — sem loading desnecessário, dados sempre atualizados
🐻 Zustand (Estado Global)

O que é: É a memória compartilhada da aplicação. Zustand é uma "loja" onde você guarda informações que várias telas precisam acessar ao mesmo tempo.

No ERP da SafeWork: O CNPJ ativo da filial selecionada, o usuário logado e o perfil de permissão ficam no Zustand. Qualquer componente de qualquer página acessa isso sem precisar "passar" de componente em componente.

📋 Papel no ERP: Estado do usuário logado, CNPJ ativo, permissões — acessível em qualquer tela
// Store do usuário logado
const useAuth = create((set) => ({
  usuario: null,
  empresa_id: null,
  perfil: 'recepcao',
  login: (u) => set({ usuario: u })
}))
⚡ SSR + SSG (Performance)

SSR (Server Side Rendering): A página é montada no servidor antes de chegar ao browser do usuário. Resultado: carregamento instantâneo e mais seguro (dados sensíveis não ficam expostos no JavaScript do cliente).

SSG (Static Site Generation): Páginas que não mudam muito (como o login ou a documentação interna) são geradas uma vez e servidas como HTML puro. Velocidade máxima.

📋 Papel no ERP: SSR para telas com dados sensíveis (faturamento, exames). SSG para páginas estáticas (login, FAQ interno)
⚡ API Routes — Como funcionam as rotas de API

O que são API Routes?

No Next.js, você pode criar um backend dentro do mesmo projeto do frontend, simplesmente criando arquivos dentro da pasta app/api/. Cada arquivo route.ts vira um endpoint de API.

É como ter um "mini-servidor" dentro do seu projeto. O browser chama /api/clientes, o Next.js executa o código do servidor, consulta o Supabase e devolve o JSON.

Exemplo de rota real no ERP

// app/api/clientes/route.ts
export async function GET(req: Request) {
  // 1. Pega o token JWT do header
  const token = req.headers.get('Authorization')
  // 2. Valida quem é o usuário
  const user = await verificarJWT(token)
  // 3. Busca dados (RLS protege)
  const { data } = await supabase
    .from('clientes')
    .select('*')
  return Response.json(data)
}

🚀 Edge Functions — O que são e por que usar

A analogia da farmácia

Imagine que você mora em Medianeira-PR e precisa de um remédio. Se o depósito central fica em São Paulo, demora. Se tem uma farmácia no bairro, é instantâneo. Edge Functions são "farmácias no bairro" — são funções que rodam em servidores espalhados pelo mundo, próximos do usuário, em vez de um servidor central.

No Supabase: Edge Functions são pequenos programas (em TypeScript/Deno) que rodam nos servidores do Supabase. Eles são perfeitos para processar webhooks que chegam de serviços externos (Itaú, FocusNFe).

🔔 Webhooks Assíncronos — Por que não esperar na tela?

O problema do forno de pizza

Imagine que você pediu uma pizza. O atendente não fica parado na frente do forno esperando. Ele te dá um número, você senta, e quando a pizza ficar pronta, ele te chama. Isso é processamento assíncrono com webhook.

No ERP, emitir uma NF pode levar de 2 a 30 segundos (a SEFAZ é lenta). Se a tela ficasse "travada" esperando, o funcionário não poderia fazer mais nada. Com webhook, ele clica em "Emitir", o sistema confirma "Enviado!", e quando a SEFAZ aprovar, a tela atualiza automaticamente.

💡 Por que isso é importante para a SafeWork?

Com 1.500 NFs por mês distribuídas em 5 CNPJs, alguns dias terão picos de emissão. Se o sistema fosse síncrono (esperando resposta na tela), uma lentidão na SEFAZ travaria a tela de todos os funcionários. Com o fluxo assíncrono, a operação continua normalmente enquanto as NFs são processadas em segundo plano.

🔐 InfoSec — Segurança da Infraestrutura de TI

⚠️ Por que segurança é CRÍTICA no ERP da SafeWork?

O ERP vai armazenar: dados médicos de 10.000 trabalhadores (sensíveis pela LGPD), informações financeiras de 10 CNPJs, chaves de APIs bancárias (Itaú) e certificados digitais. Um vazamento pode gerar multas da ANPD de até R$50 milhões e responsabilidade civil.

🔴 CRÍTICO

Row Level Security (RLS) — A Muralha do Banco

O banco de dados filtra os dados antes de entregar. Mesmo que um hacker invada o frontend da Filial A, o banco recusa entregar dados da Filial B.

Como implementar: Toda tabela com dados sensíveis recebe uma policy: CREATE POLICY "filial_isolada" ON clientes USING (empresa_id = auth.jwt()->> 'empresa_id')
🔴 CRÍTICO

Zero Credenciais no Código (Secrets)

Chaves do Supabase, token do Itaú, senha do Gateway Fiscal — NENHUMA dessas informações pode estar no código que vai para o GitHub.

Como implementar: Usar .env.local localmente e Vercel Environment Variables em produção. O arquivo .env deve estar no .gitignore.
🔴 CRÍTICO

mTLS — Autenticação Mútua com o Itaú

A API do Itaú exige que seu servidor prove sua identidade com um certificado digital antes de aceitar qualquer requisição de boleto ou Pix.

Como implementar: Certificado A1 convertido para Base64, salvo como variável de ambiente na Vercel. Código cria um https.Agent com o certificado antes de chamar a API.
🟡 ALTO

JWT com Expiração Curta + Revogação

Quando um funcionário é demitido, o token de acesso dele precisa ser invalidado imediatamente. Tokens sem expiração são uma porta aberta.

Como implementar: Supabase Auth usa JWT com expiração de 1 hora. Para revogação imediata: supabase.auth.admin.signOut(userId) invalida todos os tokens do usuário.
🟡 ALTO

Validação de Webhook (HMAC)

Quando o Itaú ou FocusNFe enviam um webhook, qualquer pessoa poderia tentar simular uma chamada falsa para "marcar um boleto como pago" sem ter pago.

Como implementar: Cada provider fornece um "Webhook Secret". Você recalcula o HMAC-SHA256 do body e compara com a assinatura enviada no header. Se não bater, rejeita.
🟡 ALTO

Rate Limiting nas API Routes

Sem limite de requisições, um atacante pode tentar 10.000 combinações de senha por segundo (ataque de força bruta) ou sobrecarregar o servidor.

Como implementar: Na Vercel, usar o middleware de rate limiting por IP. Para o login: máximo 5 tentativas / 15 minutos por IP. Bloquear automaticamente após isso.
🟡 ALTO

LGPD — Proteção de Dados Médicos

ASOs e laudos são dados de saúde — a categoria mais protegida pela LGPD. Acesso deve ser minimizado, logado e justificado.

Como implementar: Log de acesso em tabela separada (auditoria_acessos). URLs de arquivos são temporárias (signed URL de 1h). Bucket privado no Supabase Storage.
🔵 MÉDIO

Soft Delete — Integridade para Auditoria Fiscal

Deletar uma nota fiscal, cliente ou exame pode destruir evidências necessárias para auditorias da Receita Federal e do Ministério do Trabalho.

Como implementar: Toda tabela crítica tem deleted_at TIMESTAMP. Em vez de DELETE, usar UPDATE SET deleted_at = NOW(). Query padrão sempre adiciona WHERE deleted_at IS NULL.
🔵 MÉDIO

HTTPS / TLS Automático (Vercel)

Todo tráfego entre o browser do funcionário e o servidor DEVE ser criptografado. HTTP puro expõe senhas e dados médicos.

Como implementar: A Vercel gerencia certificados SSL/TLS automaticamente. Após configurar o domínio erp.safework.com.br, HTTPS é ativado em minutos sem custo adicional.
🔵 MÉDIO

Cabeçalhos de Segurança HTTP

Cabeçalhos como Content-Security-Policy, X-Frame-Options e Strict-Transport-Security protegem contra ataques como XSS e Clickjacking.

Como implementar: Configurar no arquivo next.config.ts → headers(). A IA irá gerar essa configuração automaticamente quando você pedir.

🗃️ Banco de Dados — Nomes e Convenções Corretas

Por que a tabela USUARIOS pareceu estranha?

O que você viu ("uuididPKuuidempresa_idFK...") foi só um problema de renderização do diagrama Mermaid comprimindo os tipos. As convenções estão corretas. Veja a tabela abaixo de forma legível, com a explicação de cada campo e por quê ele se chama assim.

📋 Tabela: usuarios

ColunaTipoChavePor que este nome?
id UUID PK Padrão Supabase. Gerado automaticamente. Único globalmente.
empresa_id UUID FK Convenção: tabela_referenciada + _id. Aponta para empresas.id.
nome VARCHAR(200) — Nome completo do funcionário.

📐 Convenções de Nomenclatura (snake_case)

Por que empresa_id e não empresaId?

Em bancos de dados SQL (PostgreSQL), o padrão da indústria é snake_case (letras minúsculas com underline). JavaScript usa camelCase — por isso parece diferente, mas os dois estão certos.

Coluna no BDVariável no JSSignificado
empresa_idempresaIdFK para tabela empresas
deleted_atdeletedAtData de inativação
razao_socialrazaoSocialNome empresarial

Regras de nomenclatura para o ERP

✅ Tabelas: plural, snake_case (clientes, faturas)
✅ PKs: sempre id UUID
✅ FKs: {tabela_singular}_id (cliente_id, empresa_id)
✅ Booleans: prefixo is_ (is_ativo, is_matriz)
✅ Timestamps: sufixo _at (created_at, pago_at)
✅ Status: coluna status com ENUM definido

💡 Dica para o Antigravity Ultra

No seu CONTEXT.md, inclua uma seção chamada "Convenções do Banco de Dados" com essas regras. Assim, toda vez que o agente criar uma nova tabela, ele já vai seguir o padrão sem você precisar lembrar de pedir.
